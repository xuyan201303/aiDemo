# 三文件商谈Demo — 最小范围
本包已制作三份输入样例，不包含已完成的Web Demo。
客户不做Master：上传 → SDK读取 → AI识别 → 原文预览 → 人工修正保存 → 新案件复用。
不设置独立PoC阶段，不扩展到正式用户管理、销售价、利润或数量试算。

## 使用
1. 把samples/里的3份文件放入新项目demo_inputs/。
2. instructions/01_Codex_直接制作三文件Demo.txt交给Codex。
3. 第一轮上传01和02；查看与修正A社配送手数料。
4. 第二轮新建案件，只上传03；名称应与第一轮的人工确认结果相同，本次单价9,500。
5. 最后下载当前原価単価一覧表Excel。

## 数据真实性
所有公司、案件、单价、日期都是虚构说明数据，文件内均有标记。
两份Excel同一家A社、同样的费目和条件，但报价编号、案件、日期和5行价格不同。
PDF是另一家B社同一首轮案件的报价，使用另一套表记与版面，有可选取的文字层。
金额均为原始单价，不加总、不计算卖价和利润。

## 原文定位参考（仅供演示者检查，不是实现硬编码依据）
Excel：Sheet「見積明細」；表头第11行，明细第12～16行。
演示项目：B16为配送手数料，F16为单价；首轮8,000、次轮9,500。
真实应用仍须使用SDK给出的来源位置，不按上述坐标预填答案。
PDF：1页，5条明细；可预览任一条对应页面。

## 人工修改
不要求AI故意识别错。如果AI第一次已经认识，直接说明“调整为社内采用的名称”。
目标名称由演示时用户现场输入/选择，不在文件或模型提示中预先注入。
即使名称候选相同，后续需要证明采用了真实保存记录，而不是AI再次碰巧回答相同文字。
