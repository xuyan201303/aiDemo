# 04｜开发阶段与验收

## 1. 执行方式

ChatGPT负责基线/独立レビュー；Codex负责限定范围调查、实现和验证；用户在Mac确认执行环境、提供实际证据。一个阶段通过不自动授权下一个阶段；没有commit、push、merge、发布权限。

每阶段都必须生成Review Bundle。成功、测试失败、依赖/范围阻塞分别标真实状态，保留未执行说明，不靠打包把失败改成完成。只打包限定代码、diff、基线、命令及退出码、脱敏测试和内部SHA清单；排除原始客户PDF/Excel/邮件、真实凭证、环境密钥、缓存、venv、无关仓库及SDK数据集。

## 2. 阶段划分

| 阶段 | 有限目标 | 通过条件 | 不能顺手做的事 |
|---|---|---|---|
| W0 接入边界核对 | 核对真实SDK公开方法/输出/错误/来源/资源和环境版本；记录本文与现实差距 | 能力映射＋证据位置＋差距表；SDK未修改，批量进程未干扰；明确版本与依赖候选 | 不写完整UI、不改SDK、不跑100K、不发客户文件至云 |
| W1 领域与持久化 | 在独立项目落地模型、PostgreSQL迁移、事务纠错、版本/幂等、费用概念与学习slot | 参考核心测试语义迁移；真实PostgreSQL并发/回滚/跨scope测试；别名从原文建立 | 不用SQLite测试冒充PostgreSQL验收，不用假AI证明模型效果 |
| W2 文档读取与抽取 | 真实SDK Adapter、小样本本地解析、来源链、归属、明细对账；AI port先假实现 | 来源正确、文件失败可见、原字段保持、错误/截断/不支持显式；无重复或静默丢明细 | 不偷偷开启云OCR，不猜source坐标，不执行附件宏/外链 |
| W3 三文件商谈Demo | 经许可接入真实SDK/OpenAI；制作2个Excel＋1个PDF自作样例；薄层上传、列表、吹き出し、预览、保存和Excel输出 | 第一轮Excel＋PDF→修正保存；第二轮另一Excel新案件→同条件分类复用且新价格正确；来源可预览，真实调用/疑似结果可区分 | 不建专用PoC，不扩做本番用户管理；不预先写入第3文件答案，不伪造AI误识别 |
| W4 正式业务画面与输出 | 复用W3薄层；完善登录+4画面、修改/增补/排除、案件管理、权限及Excel版本输出 | 端到端真实持久化；关闭预览不丢编辑；文件/行/版本一致；不存在“再加工”必经步 | 不加卖价/利润/数量/汇率试算，不加Master维护页 |
| W5 生产化与交付 | 权限、安全、失败恢复、部署、依赖锁定、备份/恢复、客户样本验收 | 同scope授权、文件安全、DB并发、任务失联恢复、泄漏测试、备份恢复实证和操作手册 | 不用6-10用户数代替业务量/安全实测，不宣称全部文件100%正确 |

W0～W5是内部工程分段，不是要求客户逐个购买或等待的商业阶段。W3只做商谈Demo；W4/W5是另行授权并约定范围后的正式开发。第一轮纠错到第二轮复用必须在W3真实跑通，不能把关键预览/保存功能全部拖到W4后还声称Demo已完成。

客户侧推进：Demo展示 → 需求/范围与前提整理 → 概算/正式见积 → 合同 → 本开发。必要的少量实资料确认可在范围和报价整理期间复用同一Demo完成，并非一律必须追加的阶段。Demo和约定范围的必要资料确认对客户不另收费；正式开发只计算剩余生产化工作，不重复计费。不提供未经验证的价格或工期承诺。

## 3. 学习核心必须通过的验收

1. SDK原文“送货钱”、AI曾给“配送料”、人工改“配送费”：后续匹配的是“送货钱→配送费”，不是“配送料→配送费”。
2. 新案件、新文件、金额10→20，费用分类可复用，单价必须保持新值。
3. 新数据库连接/应用重启后仍复用；不是依赖进程变量或浏览器缓存。
4. 同工作区另一名授权担当者可以复用；另一租户、错误公司scope不能直接复用。
5. 20FT→40FT、单位变化、含安装等条件变化不得套用；UNKNOWN不当作N/A或通配。
6. AI建议未人工确认时不创建ACTIVE规则；学习只在明确费用修正/确认事件生成。
7. 金额-only修正不改变名称规则；已有规则命中不会改当前币种、日期、有效期或source。
8. 同键不同人工意见进入冲突；撤销后不找到旧版再活用；明确人工解决且版本正确后才恢复。
9. 事务中断/版本冲突不出现“行已保存但规则丢失”的静默半成功；重复请求不重复创建概念/学习事件。
10. 上下文或source不足时可保存当前修正，但UI必须说明未满足自动再利用；不得假报已学习。
11. 老案件显示/旧Excel不随规则更新而被改写；重新分析不得无提示覆盖人工修正。
12. 确认名称相同不等于单位可比、金额正确或全文件已读全。

本包已完成上述部分机制的46项**离线参考测试**；完整UI/真实SDK/真实模型/正式PostgreSQL任务流程仍按阶段验证。

## 4. 三文件Demo与必要样本确认

### 固定演示输入（自作、架空数据）

| 文件 | 使用轮次 | 内容 |
|---|---|---|
| A社_初回見積.xlsx | 第1轮，与PDF同一案件 | 若干费用、单价、币种和明确条件；含可在业务中调整的费目名称 |
| B社_初回見積.pdf | 第1轮 | 同案件、不同表记，展示跨格式整理和PDF原文位置 |
| A社_次回見積.xlsx | 第2轮，独立新案件 | 含前轮相同原始费目表记及相同适用条件，金额改变；不用于预先学习 |

数据是真正的Excel/PDF文件，清楚标注架空。初轮先确认演示工作区为空学习状态（不得清空用户业务数据），完成SDK读取和实际AI调用；然后通过吹き出し修改并持久化。第二轮读取第3份文件，保存的原文→最终fee_id在同scope/context下适用，而本次价格独立取得。

第一轮无需故意制造AI错误。可以修改实际误识别，也可以将系统建议名称调整为希望的名称；两者要如实说明。注入错误只用于标为INJECTED_TEST_CASE的内部测试，不能冒充模型实际误识别。

### 演示证据

保存任务/文件哈希、SDK来源、AI调用性质、人工修正事件、学习记录版本、第2轮匹配理由、本次金额和输出文件绑定。不能把重新显示旧表、预设答案、假调用计数或占位代码当作实动完成。完整金额读取和分类调用分别记录；名称分类免调用不等于整份文件免AI。

### 工程安全测试仍保留，不要求全部对客户演示

20/40尺变化、含/不含、条件缺失、跨公司/租户、冲突/撤销、重复保存、旧Excel不变等，继续按第3节和自动化测试验证。取消独立PoC不意味着取消开发测试或本番验收。

### 必要时才复用Demo确认实资料

仅当客户有意推进且真实资料带来重要未决问题时，在约定少量资料和取扱条件后复用现有Demo。客户不必编制Master或正解台账。结果据实记录，不扩大为另一个免费项目，也不把这步作为所有概算的必经条件。

三份自作样例只证明所演示的操作与机制，不证明全部客户格式、实测精度或节省时间。具体商谈交接见docs/07。

## 5. 报告指标

分别报告读取完整性、字段正确性、费目分类、错误复用、未确认数量、修正+原文核对+最终确认时间。黄色比例不等于错误率，模型confidence不等于实测准确率。

- total_input_documents / succeeded / failed / excluded(reason) / not_processed：总数守恒。
- independently_expected_lines、found_lines、missing/extra/ambiguous：人工/独立基准照合，不能只从系统已输出行推导完整性。
- classification_memory_applied_count、eligible_exact_context_count、all_classification_rows：同时报告受限分母与全量分母，不能用小分母夸大自动化。
- extraction_ai_calls、classification_ai_calls、retry_calls、provider_usage：分开统计。参考demo中的0真实调用不说明未来AI费用为0。
- incorrect_memory_reuse_count：关注错误自动沿用；关键确定性反例须全部拦截。
- field_accuracy / classification_accuracy：公布定义、样本数和留出方式；不预先承诺95%/100%。
- human_time_baseline vs with_system：包含修改、查原文和最终核对，不只计API秒数；小样本不外推所有格式。

技术性PASS不代替正式业务验收。以下指标用于内部测试；对外只说明真正测量过的内容，不让客户在初回商谈设计评估体系。正式开发的验收范围另行合意，少量实资料确认只在必要时安排。

## 6. 每阶段最终Review Bundle

最低包含：STATUS.json；repository root/branch/HEAD/起始dirty与允许路径；精确changed paths；代码/patch；命令、退出码、日志；测试样本性质与排除项；未执行/不足项；SDK未改和外部调用是否发生；内部SHA256SUMS。

执行CRC、成员安全、内部SHA与外部ZIP SHA校验。返回ZIP、外置.sha256、VERIFICATION.txt三个绝对路径并停止等待ChatGPTレビュー。失败分支保留真实FAIL/BLOCKED，不授权自动修复/重跑/commit。打包失败则保留原证据与准确错误，不声称有ZIP。
