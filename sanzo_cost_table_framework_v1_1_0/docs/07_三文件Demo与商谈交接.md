# 07｜三文件Demo与商谈交接

**适用基线：v1.1.0，2026-09-11。演示计划，不是已运行的真实SDK/AI/Web证据。**

## 目的和边界

通过一个小型可操作Demo，让客户看到SANZO理解了原价单价表、原文核对和纠错学习三个重点。不再以专门PoC阶段推进，不另建第二套验证系统。Demo≠正式系统交付≠客户所有报价都已验证。

## 输入与操作

固定准备2个Excel和1个电子PDF，均为自制虚构业务样例，不含客户机密。第1轮A社Excel＋B社PDF属于同一案件；第2轮A社的新Excel属于另一个案件。后续表记和适用条件相同，单价改变。

第1轮：案件名→批量上传两份→实际SDK读取→必要AI识别→原价单价列表→吹き出し显示原文和位置→点击预览→修改费用名称→保存当前表、学习记录和历史。

第2轮：创建新案件→只上传第3份Excel→读取本次金额→匹配第1轮原始表记与人工最终名称→同范围/条件优先复用→展示新单价→列表保存/Excel输出。

必须记住原文→人工最终fee_id，而不是AI旧答案→新答案。第3份不能提前输入分类答案。第二轮不能只是读上次缓存；应引用真实保存的学习版本。金额变化本身不要求重新学习名称。

原文不修改；预览从真实源位置取得。PDF按页，Excel按单元格周边。未实现的Office完整样式等不表述为已完成。

## 不为演示造假

不为了保证修正环节出现而强制模型故意误识别。可使用自然的错识别或演示将名称调整为用户希望的名称。测试注入必须明示。SDK、AI、预览、保存和知识复用如果是占位/模拟/预计算结果，应明确告知；不能把参考核心或截图当作全流程实装。

本次文档修订没有生成3个业务样例文件，没有连接真实SDK/AI，没有实现实动Web Demo。这些是W3及其前置步骤的任务。对外展示前先在真实演示环境完整彩排。

## 会议分工

客户说明→我方技术担当或社长提问→島野さん公司介绍（2～3分）→島野さん提案→森田さんDemo→客户问题。

提案中不重复客户现状调查，也不在Demo前结束整场会议。岛野最后按下面交接：

```text
以上が、ご提案内容のご説明です。
ここからは、弊社の森田より、実際の画面を使ってご説明いたします。
森田さん、デモをお願いいたします。
```

森田开场：

```text
それでは、デモをご覧いただきます。
今回は、説明用に用意した3つのサンプルで、取り込みから修正、次の案件への反映までをご紹介します。
```

Demo后再邀请客户质疑。之后根据意向整理范围、概算与正式见积、合同和本开发。只有必要且得到许可时才在同一Demo上确认少量实资料，不反复免费开发，不把此确认改成一律必经的工程。

## 安全与后续开发

保持W0只读查真实SDK契约、独立业务repo、阶段限定、未授权不安装升级/收费/外传/发布、每阶段Review Bundle及停止レビュー。取消对客户单设PoC，不取消工程测试、独立复核或正式系统安全/验收。
