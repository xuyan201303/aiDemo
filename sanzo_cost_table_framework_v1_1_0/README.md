# 原価：単価一覧表システム — 实装框架 v1.1.0

**案件：No.202608310011／株式会社コクヨロジテム**  
**基线日期：2026-09-11／SANZO内部实装用**  
**状态：架构与契约基线 + 已运行测试的离线学习核心；不是完整业务系统，也不是客户最终签字规格。**

## 先看这一页

系统只做：**报价导入 → 整理并利用过去纠错 → 原価：単価一覧表 → 预览、修改 → 保存并下载Excel。**

客户不用先制作费用清单，也不维护另外一张Master。客户在正常业务中修改一次，系统自动保存“原始费用名称 → 客户确认费用”的对应关系，后续条件相同时复用。

### 一条贯穿全项目的例子

| 时间 | 原文 | 处理 | 结果 |
|---|---|---|---|
| 第一次 | 送货钱：10元 | AI建议“配送料”；客户改为“配送费” | 本次显示“配送费：10元”；记住“送货钱 → 配送费” |
| 第二次、同一公司和条件 | 送货钱：20元 | 已确认的名称直接复用，价格读取这次的20元 | “配送费：20元”；名称分类无需再次问AI |
| 新叫法 | 运输服务费：20元 | 旧记录不能直接解决，由AI结合相关案例判断 | 提出分类；不明确则客户确认 |
| 条件变了 | 送货钱（含安装）：50元 | 不能把不同服务硬套旧规则 | 单独判断、必要时确认 |

以上是说明用例，不是真实客户报价。“名称分类不用AI”不代表新文件读取全过程不用AI。

### 一套应用，六个职责

```text
客户网页：登录 + A案件上传 + B原价单价表/吹き出し/原文预览 + C案件一覧 + D用户
                                    │
                                    ▼
后台业务程序：案件、权限、任务、判断、保存、Excel
            ├── SDK适配层：原文、结构、来源位置
            ├── 已确认费用对应记录：先查已教过的内容
            ├── AI适配层：理解未知内容，不能自己写入学习记录
            ├── 业务数据库：本次报价、费用分类、修正历史
            └── 私有文件存储：原件、预览、Excel与备份
```

建议正式技术栈：React + TypeScript；Python + FastAPI；PostgreSQL；一套私有文件存储；OpenAI API。
这是实现选型，不是要求购买六个云服务。API与文档处理worker属于同一个项目；初期不做微服务、Kubernetes、独立向量数据库、模型训练平台。

## 本期做与不做

**做：**PDF/Excel/邮件正文导入；单价与条件提取；各费用分类；纠错学习；横向列表；原文预览；当前画面修正；案件管理；6～10人登录及基本用户管理；原价单价表Excel保存与下载。

**不做：**売上単価、ドレージ料利益加算、数量乘算、日元换汇试算、利润额/率。邮件自动收取、复杂权限和完整Office版式还原也不默认纳入。

**待确认但不阻碍搭框架：**原价单价表具体样式；是否等同以前提到的新系统“加工済みExcel”；是否还需第二次转换；真实样本和部署/外部AI条件。

## 最新推进方式：演示，不单设验证项目

不再安排专门的PoC阶段，也不重新开发另一套验证系统。商谈用**2个Excel＋1个PDF**的自作样例，说明我们理解的业务流程和客户最在意的纠错复用功能。

- 第一轮：A社初回Excel＋B社PDF，在同一案件上传；SDK读取、AI识别、原文预览、人工修正、保存并建立学习记录。
- 第二轮：A社的另一个Excel作为新案件；同表记与适用条件复用人工确认名称，单价取新文件的值。
- 末尾：保存原价单价表，显示Excel输出；未完成部分明确标识，不声称整个正式系统已建成。
- 客户有意推进时，直接整理范围与报价。**只有必要时**才用同一Demo确认少量实资料，不作为每次报价的必经阶段，不要求客户制作Master或正解台账。

Demo和约定范围的必要资料确认不另收费；正式开发按剩余本番工作另行报价，复用成果不重复计费。没有承诺对所有资料的精度或节省时间。

**商谈顺序：**客户说明 → 我方提问 → 島野さん公司介绍 → 島野さん提案 → 森田さんDemo → 客户提问。

**島野さん最后一句：**「ここからは、弊社の森田より、実際の画面を使ってご説明いたします。森田さん、デモをお願いいたします。」

**当前交付仍只是框架与离线参考核心，三文件实动Web Demo尚未在本包中实现。**具体演示边界见 `docs/07_三文件Demo与商谈交接.md`。

## 十条不能走样的规则

1. 学习的是**SDK所对应的原始费目表记 → 人工确认费目**，不是“AI错误答案 → 正确答案”。
2. 本次单价、币种、有效期重新读取，不从旧报价复制。
3. 同一公司/业务适用范围且条件一致才自动复用；未知条件不是任意匹配。
4. AI提出的分类不自动变成已确认学习记录；文件里的指令不能成为系统指令。
5. 普通业务修正即保存学习记录，不要求客户另做Master维护。
6. 同一键出现矛盾确认、规则被撤销或数据不可靠时，不用AI偷偷选择一个覆盖人工意见。
7. 预览来自原件及真实来源位置，原件只读；原文找不到要明确显示，不编页码/坐标。
8. 未分类明细、文件失败、未记载等不能删除或当作0；正常显示也不等于已验证正确。
9. 学习更新不自动改旧案件或旧Excel；当前修改与学习保存要有事务、版本和幂等保护。
10. 真实SDK只在适配层接入；不改SDK仓库，不中断其批量测试，不杜撰公共API。

- 固定架构、模块边界、数据契约、API草案、页面行为和阶段验收。

**未完成：**正式网页、HTTP API、PostgreSQL迁移、登录鉴权、文件解析、AI抽取/相似案例检索、OCR、PDF/Excel预览、Excel生成、生产部署、三文件实动Web演示及必要时的真实资料确认。不要把参考核心当成这些已交付。
